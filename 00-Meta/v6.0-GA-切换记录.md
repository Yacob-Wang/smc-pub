## 一、为什么升 v6

### 1.1 v5 的痛点

v5 写 Memory 系列 15 篇时,反复踩这些坑:
- 子线程 token 截断时输出乱码(aart/ / vvmscan / rameworks / ndroid: / m_kill / o.lmk 6 类 bug)
- 子线程发明 rogue marker 标签(:SELFCHECK / :begin 等变体)
- 公开站出现元信息残留(本篇定位 / 校准决策日志 / 硬性要求 等)
- 跨篇 markdown 链接用半角冒号(公开站 404)
- system prompt 渲染陷阱(子串相似字符串被规范化)
- 编造路径 / 类名 / 作者 / 时间线(2025-11-30 AOSP 17 发布 等)

### 1.2 v6 解决的 6 大问题

| # | 问题 | v5 状态 | v6 解法 |
|---|---|---|---|
| 1 | marker 嵌套混乱 | 允许嵌套 | §9.2 禁止嵌套 + 强制成对 |
| 2 | 子线程违抗 prompt | 无 | §13.1 子线程 prompt 模板 + 顶部 5 行硬性要求 |
| 3 | 子线程写入 bug | 无 | §12.2 6 类 blacklist + §13.1 prompt 必加 + verify_bug6.py |
| 4 | 公开站元信息残留 | 仅剥 5 段前言 | §9.3 扩剥离范围(内部规范号 / LLM 流程披露)+ verify_strip.py |
| 5 | 半角冒号链接 | 无 lint | §3.5 全角冒号 + verify_colon.py |
| 6 | 编造路径/类名 | 仅"标注待确认" | §12.1 blacklist 20+ 条 + §11 联网 source 标注 + verify_paths.py |

**9.1 实测**:`run_all.py scripts/verify_v6/run_all.py 01-卷1-平台基础与启动/09-SystemServer 启动/9.1-...md` → **ALL TOOLS PASS**

### 3.2 设计原则

1. **每个工具独立可执行** — 失败时能定位到具体哪个工具出问题
2. **统一退出码** — 0=PASS / 1=FAIL,方便集成到 CI
3. **统一输出格式** — `=== <tool>: <file> ===` 开头,逐项 `1. <检查项>: <n> 处 ✅/❌`
4. **用 chr() 拼字符串** — 避免 system prompt 渲染陷阱(§10.1)
5. **负向 lookbehind** — verify_bug6.py 排除 `frameworks` 等合法子串
6. **STRICT + WARN 双层** — verify_ai_words.py 分两类,严格 0 容忍 + 警告自觉
