## 序言

### 为什么写这本书

Android 稳定性是一个**横跨全栈**的工程领域——一个 ANR 可能源自 Kernel 调度、Native 库、Framework 服务、App 主线程中的任何一环。但当前市场上的资料要么是 AOSP 源码解析（Kernel / Framework 单层视角），要么是 Android 应用开发（App 层视角），**缺少「以稳定性问题为中心、横跨全栈」的体系化参考书**。

工程师排查问题时被迫在多个知识领域间反复跳跃：先看 AOSP 源码（找到机制），再翻工具手册（学会抓 trace），最后查案例库（获得参考）——**缺一条连贯的路径**。

本书用**问题导向 + 全栈贯通**的方式，把 Android 稳定性所需的知识体系重新组织为「8 卷 50 章」，覆盖从底层到应用、从机制到症状、从工具到治理的完整链路。

### 本书不讲什么

明确边界，避免读者预期错位：

| 不讲 | 原因 | 去哪里看 |
|---|---|---|
| Android 应用开发入门 | 本书假设读者能读懂 Java/Kotlin 与基本组件 | 官方 Developer 文档 |
| Jetpack / Compose 用法 | 属于应用架构，非系统稳定性 | 官方 Jetpack 文档 |
| Kernel 驱动开发 | 只讲稳定性相关的 Kernel 子系统 | 《Linux Device Drivers》 |
| 逐行源码走读 | 只在机制关键处引用源码，不做通篇注释 | AOSP 源码 + Code Search |
| 具体 OEM 的私有实现 | 只讲 AOSP 主线 + 公开的 OEM 差异模式 | 各厂商开放文档 |

# 卷 1　Android 系统基础与平台

> **本卷定位**：稳定性架构师必须理解全栈结构——硬件怎么动、Kernel 怎么调度、HAL 怎么抽象、安全模型怎么约束。**地基卷**，不读后面章节会缺基础。
> **预计字数**：~7 万字（5 章）
> **可跳读**：有 AOSP 经验者可只读第 1 章与第 4 章。

---

## 第 1 章　Android 系统全景与 AOSP 17

- **章定位**：建立 AOSP 17 的全局视图——分层架构、核心组件、进程模型、稳定性边界。后续所有章节都挂在这张地图上。
- **核心子节**：
  - 1.1 系统分层：Hardware → Kernel → HAL → Native → Runtime → Framework → App
  - 1.2 核心组件关系图：AMS / PMS / WMS / SurfaceFlinger / Binder / ServiceManager
  - 1.3 进程模型：Zygote 体系、SystemServer、App 进程的生命周期与权限边界
  - 1.4 AOSP 17 主要变化（vs 14/15/16）：Mainline 模块演进、ART 17 优化、隐私沙箱
  - 1.5 稳定性视角的系统边界：哪些归稳定性团队、哪些需要跨团队
  - 1.6 工程基线：AOSP 17.0.0_r1 + Linux 6.18 + 测试机型
- **本章小结**：稳定性工作边界 = 全栈但有侧重，重点是 Framework / Native / Kernel 三层协同。

> **子节顺序说明**：先讲「静态分层 → 组件关系 → 动态进程模型」，把版本差异（1.4）后置，避免新读者一上来就陷入版本细节。

- **本章可跳读**：只想读机制不想编译的读者可跳过，需要时再回来。

## 第 3 章　硬件抽象层（HAL）与 Treble 架构

- **章定位**：理解 vendor / system 解耦——为什么 Android 升级不必等芯片厂，以及 vendor 侧问题为什么难查。
- **核心子节**：
  - 3.1 HAL 接口设计：AIDL / HIDL 与 .hal 文件
  - 3.2 Treble 架构：vendor 与 system 解耦、VINTF 兼容性矩阵
  - 3.3 HIDL → AIDL 迁移：AOSP 17 已全面 AIDL
  - 3.4 VINTF 与 CTS：兼容性验证机制
  - 3.5 OEM / BSP 适配要点：哪些必须做、哪些可选
  - 3.6 vendor 侧问题的定位边界：日志在哪、能改什么、找谁
- **本章小结**：vendor 行为是跨平台稳定性问题的主要根因之一；HAL 抽象让 system 升级不依赖 vendor，但也让问题定位多了一道墙。

---

## 第 4 章　Linux Kernel 基础（Android 视角）

- **章定位**：Kernel 是 Android 稳定性的最底层——理解调度 / 内存 / IO / 同步才能理解 OOM、卡死、掉电。本章只讲**稳定性相关**的 Kernel 子系统。
- **核心子节**：
  - 4.1 进程调度：CFS / RT / deadline / cgroup v2
  - 4.2 内存管理：VMA / 页面回收 / OOM / LMK / PSI
  - 4.3 IO 栈：VFS / Page Cache / IO 调度 / f2fs / erofs
  - 4.4 中断与同步：workqueue / RCU / 自旋锁 / 内存屏障
  - 4.5 Kernel 日志与崩溃现场：dmesg / pstore / ramoops（卷 4 第 29 章展开分析）
  - 4.6 与 Android 的接口：Binder 驱动（卷 3 第 12 章展开）/ 网络栈（卷 3 第 17 章展开）
- **本章小结**：约 30% 的稳定性根因落在 Kernel——ANR、Native 崩溃、卡死都要下探到这一层。

> **本章过载提示**：现有素材 45 篇，建议在写作时拆为 4.A 调度 / 4.B 内存 / 4.C IO / 4.D 同步与日志 四个子章。

---

## 第 5 章　安全基础（SELinux / AVB）

- **章定位**：Android 安全模型——沙箱 + 权限 + SELinux + AVB。理解安全边界才能识别「看起来像 bug、实际是权限拒绝」的问题。
- **核心子节**：
  - 5.1 Android 安全模型：沙箱 / UID / 权限 / 签名
  - 5.2 SELinux：sepolicy / 域 / 类型 / 强制访问控制
  - 5.3 权限框架：Android Permission / Runtime Permission / AppOps
  - 5.4 AVB（Android Verified Boot）：启动验证链
  - 5.5 权限拒绝类问题的调查方法：从 avc denied 反推策略
- **本章小结**：权限失败 ≠ 应用问题，可能是 SELinux 拒绝或 AVB 校验失败——这类问题的日志特征与普通崩溃完全不同。

# 卷 2　系统启动

> **本卷定位**：启动链路是稳定性问题的重灾区——开机卡顿 / 启动崩溃 / 开机黑屏 / 启动耗电都在这里查。**按启动时序逐章展开**，是全书唯一严格按时间顺序组织的卷。
> **预计字数**：~9 万字（6 章）

## 第 6 章　Bootloader 到 Kernel

- **章定位**：启动链路第一阶段——硬件怎么把控制权移交给 Kernel。
- **核心子节**：
  - 6.1 Bootloader 类型：LK / ABL（Android Bootloader）/ U-Boot
  - 6.2 Bootloader 启动流程：PBL → ABL → Kernel
  - 6.3 Kernel 启动入口：head.S / start_kernel
  - 6.4 早期初始化：setup_arch / sched_init / page_alloc
  - 6.5 Kernel cmdline 与 dtb：设备树 + 内核参数
  - 6.6 启动失败：Kernel panic / boot loop 的现场与分析
- **本章小结**：Kernel 启动阶段出问题 = boot loop，唯一证据是 last_kmsg / pstore，抓不到就无法定位。

---

## 第 7 章　Init 进程与 init.rc

- **章定位**：第一个用户态进程——整个 Android 系统的「启动管家」。
- **核心子节**：
  - 7.1 Init 进程（system/core/init）启动流程

- **本章小结**：init 阶段慢会 gating 后续所有服务——这里省 1 秒，整机启动省的往往不止 1 秒。

## 第 8 章　Zygote 与 ART 启动

- **章定位**：Java 进程工厂——所有 App 进程的模板。ART 的完整机制见卷 3 第 20 章，本章只讲**启动阶段**。

- **本章小结**：Zygote 是所有 App 启动的公共瓶颈——它慢 1 次，全系统慢 N 次。

## 第 12 章　Binder IPC 深度

- **章定位**：Android 唯一的通用跨进程通信机制——理解 Binder 才能理解绝大多数跨进程卡死。
- **核心子节**：
  - 12.1 Binder 驱动：mmap / 引用计数 / 线程池
  - 12.2 Binder 协议：BC / BR 命令 / Parcel / flat_binder_object
  - 12.3 Java 框架层：AIDL / ServiceManager / DeathRecipient
  - 12.4 调用模式：同步 / oneway / 事务大小限制
  - 12.5 完整调用链路：客户端 → 驱动 → 服务端 → 返回
  - 12.6 Binder 卡死排查：线程池耗尽 / oneway 堆积 / 跨进程死锁
- **本章小结**：Binder 阻塞是 ANR 的头号跨进程根因——看 ANR trace 先确认主线程是否卡在 Binder 上。

## 第 13 章　进程与生命周期

- **章定位**：进程是 Android 的资源分配单位——理解进程模型才能理解 OOM、LMK 与杀进程。
- **核心子节**：

  - 13.2 进程优先级：oom_score_adj / ProcessList / cgroup 分组
  - 13.3 四大组件与进程生命周期的绑定关系
