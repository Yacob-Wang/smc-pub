# 10.2 进程创建:Zygote fork 的应用侧参数

## 一句话开场

ATMS 请求 Zygote fork 应用进程时,会传 **7 类参数**(uid / gid / gids / runtimeFlags / mountExternal / seInfo / niceName),每类错配都会触发不同症状(uid 错 = 权限错 / seinfo 错 = SELinux 拒绝 / niceName 错 = ps 看不到应用名)。本节把 7 类参数逐项拆开讲,让读者在 fork 慢/seinfo 错/进程名乱时能 30 秒定位到具体哪一类参数。

## 1. 核心子问题

1. ATMS 调 `Process.start()` 时传哪 7 类参数?
2. `uid` / `gid` / `gids` 怎么确定?应用专属 vs shared UID?
3. `runtimeFlags` 包含哪些标志?DEBUGGABLE / PROFILEABLE 各代表什么?
4. `mountExternal` 怎么影响外部存储挂载?
5. `seInfo` 是什么?SELinux 上下文怎么定?
6. `niceName` 怎么设?默认是包名吗?
7. 7 类参数错配的常见症状?各对应哪些 logcat 关键词?
8. AOSP 17 vs AOSP 14 的 fork 参数差异?

## 2. 详细展开

### 2.1 7 类参数的总览:ATMS → Zygote

**10.1 §2.4 已讲过 Process.start() 是 Zygote fork 应用的入口**。本节展开 7 类参数:

```
[system_server 进程]
ActivityTaskManagerService.startActivityAsUser
  → 决定要 fork 哪个进程
  → 调 Process.start(... 7 类参数 ...)
[跨进程:Process → ZygoteProcess]
ZygoteProcess.start(...)
  → 通过 socket 通信到 zygote 进程(8.1 §2.6)
[zygote 进程]
ZygoteInit.forkAndSpecialize(... 7 类参数 ...)
  → Zygote.forkAndSpecialize(... 7 类参数 ...)
  → fork() 后处理 7 类参数
  → 子进程 = ActivityThread.main()
```

**7 类参数总览表**:

| # | 参数 | 类型 | 决定者 | 错配症状 |
|---|---|---|---|---|
| 1 | `uid` | int | PMS 解析 manifest 的 sharedUserId | 权限错 / 数据目录不可访问 |
| 2 | `gid` | int | PMS 解析 | 资源访问错 |
| 3 | `gids` | int[] | PMS 解析 `<uses-permission>` | 设备节点访问错 |
| 4 | `runtimeFlags` | int | ATMS 推导(DEBUGGABLE / PROFILEABLE 等) | 调试器无法附加 / 性能 profile 失效 |
| 5 | `mountExternal` | int | 设备状态(encrypted / unmountable) | 外部存储挂载错 |
| 6 | `seInfo` | String | PMS 解析 manifest 的 `android:sharedUserId` + SELinux 策略 | SELinux avc 拒绝 |
| 7 | `niceName` | String | ATMS 推导(包名 / 进程名) | `ps` 看不到 / `dumpsys` 找不到 |

### 2.2 参数 1-3:uid / gid / gids(Linux 身份)

**uid / gid 是 Linux 进程身份**,由 PMS 在解析 apk manifest 时决定。

**uid 的确定逻辑**:
- 普通应用:`uid = 10000 + N`(N 是用户安装顺序),如 `10000 / 10001 / 10002 ...`
- system app:`uid` 由 manifest 决定(常在 `system/etc/permissions/privapp-permissions-*.xml`)
- shared UID:`uid` 是 manifest 声明的 `android:sharedUserId`,如 `android:sharedUserId="android.uid.system"` → `uid = 1000`

**gid / gids 的确定逻辑**:
- `gid` 默认等于 `uid`(一个进程的"主组")
- `gids` 是从 `<uses-permission>` 推导——某些 permission 关联一个 gid(在 `/system/etc/permissions/platform.xml` 中)

```xml
<!-- /system/etc/permissions/platform.xml -->
<permission name="android.permission.INTERNET" >
    <group gid="inet" />
</permission>
<permission name="android.permission.READ_EXTERNAL_STORAGE" >
    <group gid="sdcard_r" />
</permission>
```

**对读者有什么用**:
- `uid` 错 = 应用看不到自己的数据(/data/data/<pkg>)或别人的数据
- `gid` 错 = 应用对设备节点无访问权(如 `inet` gid 才能访问网络 socket)
- `gids` 错 = 应用无法读 / 写 / 执行特定设备文件

### 2.3 参数 4:runtimeFlags(运行时标志)

**runtimeFlags** 是一组 int 标志位,定义应用的运行时属性。常见标志:

| 标志位 | 含义 | 谁设置 |
|---|---|---|
| `DEBUGGABLE` (0x1) | 进程可被 debugger 附加 | manifest 的 `android:debuggable="true"` / ro.debuggable |
| `PROFILEABLE` (0x4) | 进程可被 `simpleperf` 采样 | manifest 的 `android:profileable="true"` |
| `PROFILE_FROM_SHELL` (0x8) | 进程可被 shell profile | shell 命令 `am profile start` |
| `NATIVE_DEBUGGABLE` (0x10) | native 库可被调试 | 类似 DEBUGGABLE |
| `BOOT_TIMING` (0x100) | 进程打 boot timing 日志 | 系统级 |
| `ISOLATED` (0x1000) | 进程在 isolated SELinux 域 | 特殊场景 |
| `DUMPABLE` (0x10000) | 进程可被 coredump | 类似 DEBUGGABLE |

**对读者有什么用**:
- `DEBUGGABLE` 错 = 调试器无法附加 / `Debug.isDebuggerConnected()` 永远 false
- `PROFILEABLE` 错 = simpleperf 拿不到数据
- `BOOT_TIMING` 错 = 启动时间 logcat 看不到 `Boot_TIMING_*` 关键事件

### 2.4 参数 5-6:mountExternal + seInfo(存储 + SELinux)

**mountExternal** 决定应用进程的外部存储挂载模式:

| 值 | 含义 | 何时设 |
|---|---|---|
| `STATE_UNKNOWN` (0) | 默认 | 旧版 |
| `STATE_UNMOUNTED` (1) | 不挂载 | 加密设备 |
| `STATE_CHECKING` (2) | 检查中 | 启动时 |
| `STATE_MOUNTED` (3) | 已挂载 | 正常运行 |
| `STATE_MOUNTED_READ_ONLY` (4) | 只读挂载 | 加密且无密码 |
| `STATE_FORMATTING` (5) | 格式化中 | 异常 |
| `STATE_NOT_SUPPORTED` (6) | 不支持 | 设备无外置存储 |

**seInfo** 是 SELinux 上下文标签,格式 `domain:seprocess`:
- 普通应用:`platform:app_process` 或 `untrusted_app:app_process`
- system app:`system_app:system_app_process`
- shared UID:`platform:shared_app_process`

**对读者有什么用**:
- `mountExternal` 错 = 应用看不到外置存储(SD 卡)
- `seInfo` 错 = **SELinux avc 拒绝**(9.4 / 9.6 已讲,案例 2)

### 2.5 参数 7:niceName(进程名)

**niceName** 是应用进程的"显示名",在 `ps` / `dumpsys` 中显示:

- 默认:`<application>` 的 `android:process` 属性(无此属性则 = 包名)
- 例:`com.example.app` / `com.example.app:remote` / `:bg`

```java
// path: frameworks/base/services/core/java/com/android/server/wm/ActivityTaskManagerService.java
// commit: android-17.0.0_r1
final int startActivityAsUser(...) {
    ...
    final String niceName = ...; // 包名 / processName
    Process.start(entryPoint, processClass, uid, gid, gids, runtimeFlags,
                  mountExternal, seInfo, niceName, ...);
    ...
}
```

**对读者有什么用**:
- `niceName` 错 = `ps` 看不到应用名,`dumpsys meminfo` 找不到
- `android:process=":bg"` 是后台进程,会单独 fork 一个进程(同包名但不同进程)

### 2.6 7 类参数常见错配速查

| 错配症状 | logcat 关键词 | 怀疑参数 | 修复 |
|---|---|---|---|
| 看不到自己的数据 | `Permission denied` 写 `/data/data/<pkg>` | uid 错 | 检查 manifest 的 sharedUserId |
| 无法访问网络 | `socket: Permission denied` | gid 错(缺 `inet` gid) | 检查 `<uses-permission INTERNET>` |
| 调试器无法附加 | `Unable to open debugger connection` | runtimeFlags.DEBUGGABLE 错 | 改 `android:debuggable="true"` |
| SELinux avc 拒绝 | `avc: denied { ... }` | seInfo 错 | 9.4 §4 案例 2 详述 |
| 进程名乱码 | `ps` 输出 `:???` 或随机 | niceName 错 | 检查 manifest 的 `android:process` |
| 外部存储不可见 | `ExternalStorage is not accessible` | mountExternal 错 | 检查设备加密状态 |
| 设备节点访问拒绝 | `Permission denied` 读 /dev/* | gids 错 | 检查 platform.xml 的 group 映射 |

### 2.7 AOSP 17 vs AOSP 14 的 fork 参数差异

| 维度 | AOSP 14 (API 34) | AOSP 17 (API 37) | 变化 |
|---|---|---|---|
| 7 类参数数量 | 7 | 7 | 无变化 |
| runtimeFlags 新增 | 0x100 BOOT_TIMING | +0x200 PROC_STATE | +1 |
| mountExternal 模式 | 6 状态 | 8 状态(新增 LEGACY / SHARED) | +2 |
| seInfo 标签 | platform:app_process | 同 | 无变化 |
| niceName 默认 | 包名 | 包名 | 无变化 |
| 进程池(USAP) | 默认 4-10 | 默认 4-10 | 无变化 |

> **🟡 待联网确认**:runtimeFlags 新增 0x200 PROC_STATE 为待联网确认,实际以 AOSP 17 build 为准。

## 4. 实战案例

### 案例 1:某 App 启动慢 1s,定位 fork 时 USAP 池未命中(典型模式)

**环境**:
- Android 版本:基于 AOSP 14 定制
- 设备:某品牌中端机(代号 wolf,6GB RAM)
- 复现步骤:用户反馈某 App 启动慢 1 秒,冷启动 1.5s(基线 500ms)

**现象**:
```bash
$ adb shell am start -W -n com.example.app/.MainActivity
ThisTime: 1500
TotalTime: 1700
```
**关键观察**:ThisTime 1.5s,TotalTime 1.7s——ThisTime 占 88%,但基线 500ms,慢 1 秒。

**分析思路**:
1. 抓 Perfetto boot trace,看 7 个事件名
2. `am_proc_start → am_proc_bound` 差值 800ms(基线 50-150ms)
3. **根因**:Zygote 每次 fork 应用都要走完整 8.1 §2.6 流程(preload → select loop → fork)
4. 但 USAP 池可以"预先 fork"一批 Zygote 子进程,App 启动时**直接命中 USAP**,省 600-800ms
5. 检查 USAP 池配置:`adb shell getprop dalvik.vm.usap_pool_size` → 2(默认 4-10)
6. **该设备 OEM 改小了 USAP 池到 2**

**根因**:
- 8.1 §2.6 已讲 USAP 池是 AOSP 11+ 的优化,可以省 60-80ms 每次 fork
- 该 OEM 为了省内存,把 USAP 池从默认 4-10 改成 2
- USAP 池 2 → App 启动时命中 USAP 概率低 → 大部分 fork 走完整路径 → 慢 600-800ms

**修复**:
- 短期:`adb shell setprop dalvik.vm.usap_pool_size 8` (root 设备)
- 中期:OEM 修改 `dalvik.vm.usap_pool_size` 默认值
- 长期:升级 AOSP 17,USAP 池默认 4-10

**修复原理**:
- USAP 池 2 vs 8 内存差 = 6 × Zygote 子进程 × (RSS 50-100MB) = 300-600MB
- 4GB 设备权衡:USAP 池 2(省内存)/ 8(快启动)
- 8GB 设备:USAP 池 8(快启动优先)

### 案例 2:某 App 启动时 avc: denied,定位 seinfo 标签错(典型模式)

**环境**:
- Android 版本:基于 AOSP 13 定制
- 设备:某品牌中端机(代号 eagle,4GB RAM)
- 复现步骤:装某第三方金融 App(代号 FinanceApp)后,启动立即崩

**现象**:
```log
$ adb logcat -d -s ActivityManager,DEBUG,AndroidRuntime -t 100
ActivityManager: Process com.finance.app has died
DEBUG: avc: denied { read } for comm="system_server"
      scontext=u:r:system_server:s0
      tcontext=u:r:untrusted_app:s0 tclass=file
AndroidRuntime: FATAL EXCEPTION: main
  at android.os.BinderProxy.transactNative(Native method)
```
**关键观察**:App 启动后立即死 + avc: denied + scontext=system_server + tclass=file。

**分析思路**:
1. 关键日志 avc: denied → SELinux 拒绝
2. scontext=system_server → 是 system_server 端触发
3. tclass=file + tcontext=untrusted_app → system_server 想读 untrusted_app 域的文件
4. **这通常是 seinfo 错配导致的**:FinanceApp 用了 shared UID `android.uid.system` 但没声明对应的 SELinux 域
5. 查 FinanceApp manifest:`android:sharedUserId="android.uid.system"`(错!金融 App 不应共享 system UID)
6. **这意味着 FinanceApp 应在 system_app 域,但实际 seinfo 设了 platform:app_process**

**根因**:
- FinanceApp 用了 `android:sharedUserId="android.uid.system"` 但**没**把自己放到 system 分区
- PMS 解析 manifest 时,看到 `sharedUserId="android.uid.system"` → uid=1000,但 seinfo 仍然用 `platform:app_process`(因为不在 system 分区)
- uid=1000 但 seinfo 是 platform 域 → SELinux 不允许
- 进程被 fork 后,system_server 想读其文件(因 uid=1000 暗示是 system app)→ avc: denied

**修复**:
- 短期:FinanceApp 改 manifest,移除 `android:sharedUserId="android.uid.system"`
- 中期:OEM 校验 sharedUserId 必须配套 seinfo
- 长期:升级 AOSP 17,SELinux 规则更严

**修复原理**:
- `sharedUserId` + `seInfo` 必须配套——uid 暗示 SELinux 域,不能错配
- 9.4 §4 案例 2 已讲过类似问题(ProCam vendor 域)
- 调试方法:`adb shell setenforce 0` 临时关闭 SELinux 验证

## 5. Takeaway

1. **Zygote fork 应用时传 7 类参数**(uid / gid / gids / runtimeFlags / mountExternal / seInfo / niceName),每类错配都会触发不同症状。
2. **uid 错 = 权限错**——应用看不到自己的数据(/data/data/<pkg>)或别人的数据。
3. **gid 错 = 资源访问错**——应用对设备节点无访问权(如 `inet` gid 才能访问网络 socket)。
4. **seInfo 错 = SELinux avc 拒绝**——9.4 / 9.6 已讲,本节是应用侧镜像。
5. **niceName 错 = `ps` 看不到**——`adb shell ps -A | grep <pkg>` 找不到应用。
6. **runtimeFlags 错 = 调试器 / profile 失效**——`DEBUGGABLE` 标志影响 debugger 附加。
7. **USAP 池命中率低是 fork 慢的常见根因**——OEM 改小 USAP 池到 2(默认 4-10)会让 App 启动慢 600-800ms。
8. **`sharedUserId` + `seInfo` 必须配套**——uid 暗示 SELinux 域,不能错配。9.4 §4 案例 2 已讲过类似问题。
