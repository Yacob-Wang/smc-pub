## 3. Step 2:15min 复现

### 3.1 复现脚本

```bash
# 3.1 启动相机 App
$ adb shell am start -n com.example.camera/.MainActivity
sleep 5

# 3.2 切换到 12MP 模式
$ adb shell input tap 540 1500  # 模拟点击设置
sleep 2
$ adb shell input tap 800 1200  # 模拟点击 12MP 选项
sleep 3

# 3.3 拍照 10 次(每次 + 抓 proc/meminfo)
for i in $(seq 1 10); do
    echo "=== 第 $i 次拍照 ==="
    adb shell input keyevent KEYCODE_CAMERA  # 模拟拍照按钮
    sleep 3
    # 抓关键指标
    echo "[第 $i 次] CmaFree:"
    adb shell cat /proc/meminfo | grep "CmaFree"
    # 拍照 12MP 失败?
    FAIL=$(adb logcat -d | grep -c "dma_alloc_from_contiguous" || true)
    echo "[第 $i 次] dma_alloc 失败次数: $FAIL"
done
```

### 3.2 预期输出

```
=== 第 1 次拍照 ===
[第 1 次] CmaFree:  4096 kB     ← 还有 4MB
[第 1 次] dma_alloc 失败次数: 0
=== 第 2 次拍照 ===
[第 2 次] CmaFree:  0 kB          ← 用光了!
[第 2 次] dma_alloc 失败次数: 1   ← 失败
=== 第 3 次拍照 ===
[第 3 次] CmaFree:  0 kB
[第 3 次] dma_alloc 失败次数: 2
...
```

**关键识别**:
- 第 1 次后 CmaFree=4096KB(还有 4MB)
- 第 2 次后 CmaFree=0(用光!)→ 12MP 拍照分配失败
- 第 2-10 次全部失败(因为 CmaFree=0 不恢复)

### 3.3 实时监控 zoneinfo

```bash
# 持续监控 Normal zone free(对照是否恢复)
$ watch -n 5 "adb shell cat /proc/zoneinfo | grep -A 3 Normal"
```

**预期**:`free` 不会恢复(因为没有进程释放 CMA)→ **永久 0**

## 5. Step 4:30min 分析(链 3 + CmaFree=0 + 0 字节文件)

### 5.1 链 3 信号识别(对应 26.5 §2.3)

对照 0xffffff13 抓取,链 3 信号完整:

| 链 3 信号 | 0xffffff13 表现 | 判定 |
|----------|----------------|:----:|
| `CmaFree = 0` | 0 kB | ✅ 命中 |
| `pgscan_kswapd > 1000/s` | 5.4 万/s | ✅ 命中 |
| `compact_stall > 100` | 135 | ✅ 命中 |
| **拍照 12MP 分配失败** | **复现** | **直接证据** |

**关键识别**:**完整命中链 3 模式**——CMA 满 → 大块 DMA 分配失败 → 拍照降级

### 5.3 完整根因分析

```
[链 3 完整根因链]
1. 系统启动时 ION heap 划分
   ├─ system heap: 128MB(93% 占用)
   ├─ system_contig: 128MB(87%)
   ├─ cgpu: 64MB(98%)            ← ⚠️ 满载
   └─ secure: 64MB(87%)

2. 用户操作(打开相机 12MP)
   ├─ 相机 App 申请 12MB DMA buffer
   ├─ 内核 dma_alloc_from_contiguous() 调用
   ├─ 遍历 CMA heap 找 12MB 连续块
   └─ 找不到(CmaFree=0)→ 失败

3. 拍照降级
   ├─ 12MP → 8MP(只需 6MB)
   ├─ 仍然找 6MB 连续块
   └─ 仍然找不到 → 完全失败

4. 用户体验
   └─ 拍照按钮无效 / 黑屏 / 卡死
```

### 5.4 ION heap 谁吃了 87%+?

| Heap | 占用 | 占用方 | 优化方向 |
|------|------|--------|----------|
| **cgpu 63/64MB (98%)** | 相机/视频 | **减小 12MP buffer 缓存上限** | 6MB → 4MB |
| **system 120/128MB (93%)** | 系统服务 | **复审 system service 持 ION** | 短期难 |
| **secure 56/64MB (87%)** | TrustZone | **减小 secure buffer** | 24MB → 12MB |
| **system_contig 112/128MB (87%)** | 通用 | **减小 video buffer** | 32MB → 16MB |

**关键识别**:**cgpu 98% 是主因**——相机/视频 GPU buffer 累积 + secure buffer 占用大

### 6.2 中期修复(1-2 周,需 OEM 配合)

**给 OEM 反馈模板**:

```

================================================================

# 增大 cgpu heap
# 在 device tree / kernel config 中:
# CONFIG_ION_CGPU_SIZE=96M     # 默认 64M
```

| Step 5 方案 | 10min | 8min | 短期 + 给 OEM 反馈 |
| **总计** | **65min** | **54min** | **30 分钟内出短期 + 反馈** |

### 7.2 关键收获

1. **CmaFree=0 直接链 3 信号** ← 1 行命令就定位
2. **ION heap 详情** 找谁吃了 87%+ ← 对应 26.9 §3
3. **mmstat2 时间序列** 看 1Hz 趋势
4. **0 字节文件判别 3 步法** 对应 26.9 §6
5. **OEM 反馈模板** 是关键交付

### 7.3 改进建议

- **APM 监控** 应在拍照 App 集成前就开启
- **CMA 划分** 应在产品定义时定好,不是上线后改
- **mmstat2** 应该 7×24 持续采集,不是故障时才看

## 8. 总结:5 条 Takeaway

读这篇应能回答:

1. **"CmaFree=0 意味着什么?"** ——
   - **典型链 3 信号**:CMA 满 → 大块 DMA 分配失败
   - 后果:拍照 12MP 失败 / 视频 4K 失败 / AI 推理失败
   - 跟 MemFree 不同(物理内存 vs CMA 连续区)

2. **"ION 4 大 heap 谁吃了空间?"** ——
   - **cgpu 98%** ← 相机/视频 GPU(主因)
   - **system 93%** ← 系统服务
   - **secure 87%** ← TrustZone
   - **system_contig 87%** ← 通用

3. **"0 字节文件怎么判别?"** ——
   - 3 步法:路径存在 → 权限 → 触发条件
   - 4 大根因:抓取失败 / 路径变化 / 功能未启用 / 运行时无数据

4. **"CMA 治理 5 大动作?"** ——
   - 减小 secure buffer(24MB → 12MB)
   - 调整 cgpu heap(64MB → 96MB)
   - 调整 CMA 池(cma=480M → 512M)
   - 优化相机 buffer 缓存
   - 长期 APM 监控

5. **"为什么 0xffffff13 抓 12MP 失败?"** ——
   - CmaFree=0(链 3 信号)+ ION cgpu 98% 占用
   - 12MP 拍照申请 12MB DMA buffer 失败
   - 8MP 降级也失败(cgpu 几乎满)
   - **核心**:cgpu heap 长期吃紧 + secure buffer 占用大

### E.1 CMA 占用检测脚本 `detect_cma_full.sh`

```bash
#!/bin/bash
# detect_cma_full.sh
# 用途:检测 CmaFree 趋势 + ION heap 占用
# 用法:./detect_cma_full.sh

set -e
DURATION="${1:-60}"  # 1 小时
INTERVAL=300  # 5min
LOG="/tmp/cma-monitor-$(date +%Y%m%d-%H%M%S).csv"
echo "timestamp,CmaFree_KB,MemFree_KB,MemAvailable_KB,cgpu_heap_used_pct" > "$LOG"

START_TIME=$(date +%s)
ELAPSED=0
while [ "$ELAPSED" -lt "$DURATION" ]; do
    # 1. 抓 proc/meminfo
    MEMINFO=$(adb shell cat /proc/meminfo)
    CMA_FREE=$(echo "$MEMINFO" | grep "CmaFree:" | awk '{print $2}')
    MEM_FREE=$(echo "$MEMINFO" | grep "MemFree:" | awk '{print $2}')
    MEM_AVAIL=$(echo "$MEMINFO" | grep "MemAvailable:" | awk '{print $2}')

    # 2. 抓 ION cgpu heap 占用
    if [ -f "/tmp/ion-camera.txt" ]; then
        CGPU_PCT=$(grep -oP "used: \K0x[0-9A-F]+" /tmp/ion-camera.txt 2>/dev/null | head -1)
        # 简化:用 grep 找百分比
        CGPU_PCT=$(echo "98")  # 实战时根据实际值填
    else
        CGPU_PCT="N/A"
    fi

    echo "$(date -Iseconds),$CMA_FREE,$MEM_FREE,$MEM_AVAIL,$CGPU_PCT" >> "$LOG"

    # 3. 告警
    if [ "$CMA_FREE" -eq 0 ] 2>/dev/null; then
        echo "⚠️ 告警:CmaFree=0(链 3 信号)" | tee -a "$LOG"
    fi

    echo "[$(date -Iseconds)] CmaFree: ${CMA_FREE} KB"
    sleep "$INTERVAL"
    ELAPSED=$(( $(date +%s) - START_TIME ))
done

echo "=== 检测完成,日志: $LOG ==="
```

(完整可复制)

### E.2 ION heap 抓取脚本 `dump_ion_heaps.sh`

```bash
#!/bin/bash
# dump_ion_heaps.sh
# 用途:抓所有 ION heap 详情
# 用法:./dump_ion_heaps.sh

set -e
OUT_DIR="${1:-/tmp/ion-heaps-$(date +%Y%m%d-%H%M%S)}"
mkdir -p "$OUT_DIR"

echo "=== ION heap 抓取 ===" | tee "$OUT_DIR/log.txt"

# 1. 系统级
adb shell ls -la /d/ion/ > "$OUT_DIR/ion-ls.txt" 2>&1

# 2. 通用 ION debugfs
adb shell cat /d/ion/ion_heap_debug > "$OUT_DIR/ion-heap-debug.txt" 2>&1
adb shell cat /d/ion/heaps/system > "$OUT_DIR/ion-system.txt" 2>&1

# 3. 各专用 heap
for heap in system system_contig cgpu gpu secure carveout; do
    adb shell cat /sys/kernel/debug/ion/heaps/$heap > "$OUT_DIR/ion-$heap.txt" 2>&1 || true
done

# 4. ION 历史(可能 0 字节)
adb shell cat /d/ion/ion_history > "$OUT_DIR/ion-history.txt" 2>&1 || true

# 5. DMA-BUF
adb shell cat /d/dma_buf/bufinfo > "$OUT_DIR/dma-buf-info.txt" 2>&1
adb shell cat /d/dma_buf/new_bufinfo > "$OUT_DIR/dma-buf-new.txt" 2>&1

echo "=== 抓取完成: $OUT_DIR ==="
ls -lh "$OUT_DIR"
```
