### 26.2 Java OOM 堆溢出 / 大对象 / Bitmap / 线程数超限

**一句话定位**:**Java 堆 4 大 OOM 类型逐一讲——logcat 怎么识别、hprof 怎么定位、ART 内部哪条路径触发、典型阈值与修复方向。**

**章节结构(7 节 + 4 附录)**:
- §1 背景:Java OOM 为什么占线上 P0 50%+
- §2 4 大 OOM 类型总览
  - 类型 1:**堆溢出**(`OutOfMemoryError: Java heap space`)—— 持续分配超过 `JavaHeapLimit`
  - 类型 2:**大对象**(`OutOfMemoryError: Failed to allocate a ... byte allocation`)—— 单次分配超过 GC region
  - 类型 3:**Bitmap 泄漏**(`OutOfMemoryError: Out of memory on a ... byte allocation`)—— Graphics 涨速 > 10MB/min
  - 类型 4:**线程数超限**(`java.lang.OutOfMemoryError: pthread_create ... failed`)—— Thread 总数 > 1 万
- §3 堆溢出深入:ART 堆增长机制(从 16MB 增长到 256MB/512MB 的水线)
- §4 大对象深入:GC region 大小(> 256KB 走 Large Object Space,直接 OOM)
- §5 Bitmap 泄漏深入:Native 像素 + Java 引用 的解耦机制
- §6 线程数超限深入:Thread native 栈 1MB × N 撑爆进程虚拟地址
- §7 实战案例(2 个) + §8 总结 5 条 Takeaway
- 附录 A-D

**章节结构(7 节 + 4 附录)**:

- §6 scudo 分配器:6 大原则 + TLS 缓存 + Quarantine

### 26.4 进程被杀:LMK 判定链路与「优先级误配」型误杀

**一句话定位**:**杀进程的 3 大触发路径(用户态 OOM / lmkd 主动杀 / 内核 OOM killer)+ 4 大 adj 误配模式——每种讲透"日志怎么识别 / 哪个机制触发 / 修复方向"。**

**章节结构(7 节 + 4 附录)**:
- §1 背景:杀进程是"症状",不是"根因"——90% 的"App 莫名被杀"是 adj 误配
- §2 杀进程 3 大触发路径
  - 路径 1:**lmkd 主动杀**(`lmkd` 日志 "Kill ..." + adj < victim adj)
  - 路径 2:**内核 OOM killer**(`vmstat:oom_kill` 计数 + dmesg "Out of memory: Killed process")
  - 路径 3:**用户态主动杀**(`am force-stop` / `kill -9`)
- §3 lmkd 判定链路:memcg PSI → AMS updateOomLevels → lmkd poll
- §4 adj 误配 4 大典型
  - 误配 1:vendor service 长期 Bnd Fgs(0xffffff13 kolun.aiservice 12%)
  - 误配 2:App 长期 Top 但 adb 看不在前台
  - 误配 3:GMS 拆 5 子状态各 5% 总和超 30%
  - 误配 4:ime 240MB 长期 Perceptible
- §5 「优先级误配」型误杀识别:`dumpsys_procstats` 子状态分布 + adb 看不在前台
- §6 修复方向:vendor service 解绑 / 调整 lmkd 阈值 / Activity finish
- §7 实战案例(2 个) + §8 总结 5 条 Takeaway

### 26.5 内存压力的连锁反应:GC 抖动 → 掉帧 → ANR

**一句话定位**:**内存压力如何从"系统水位低"传导到"用户感知卡顿"——5 个传导链 + 3 个时间窗口识别 + 治理顺序。**

**章节结构(7 节 + 4 附录)**:
- §1 背景:用户报"卡"但 dump 看不出问题——其实是 GC 抖动导致的"隐形卡顿"
- §2 5 大传导链
  - 链 1:RAM 满 → kswapd 跑 → GC 频繁 → 应用主线程 block → 掉帧
  - 链 2:foreground App 涨 → zRAM swap → IO 争抢 → 应用主线程 block
  - 链 3:CMA 满 → 拍照/视频分配失败 → 用户操作失败
  - 链 4:NUMA 失衡 → 远端内存访问 → 性能下降
  - 链 5:PSI full > 5% → 整个系统 100% 跑 kswapd → 所有进程 block
- §3 3 个时间窗口识别
  - 窗口 1:毫秒级(GC pause)—— `art` logcat `Background concurrent copying GC` 耗时
  - 窗口 2:百毫秒级(掉帧)—— `dumpsys gfxinfo` Janky frames
  - 窗口 3:秒级(ANR)—— 主线程 block 5s+
- §4 GC 类型与机制:5 大 GC 类型 + 5 大类触发条件
- §5 压力检测工具:26.7 PSI + 26.8 dumpsys + perfetto
- §6 治理顺序:先 1)释放后台 → 2)调 GC 频率 → 3)扩容硬件
- §7 实战案例(2 个) + §8 总结 5 条 Takeaway
- 附录 A-D
