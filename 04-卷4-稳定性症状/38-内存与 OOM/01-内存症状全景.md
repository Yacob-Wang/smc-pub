## 1. 背景:内存症状 90% 是"伪装"

工程师每天处理线上 P0,**内存问题很少直接暴露**——它通常伪装成卡顿、ANR 或"应用莫名被杀"。

### 1.1 4 大伪装模式

| # | 用户报 | 实际是内存问题 | 占比 |
|:-:|--------|----------------|:----:|
| 1 | "App 卡死" | 内存压力 → GC 频繁 → 掉帧 | 35% |
| 2 | "App 闪退" | Java OOM(26.2)/ Native 增长(26.3) | 30% |
| 3 | "App 莫名被杀" | adj 误配 + lmkd 误杀(26.4) | 20% |
| 4 | "系统整个慢" | RAM 满 + kswapd 跑 + PSI full(26.5) | 15% |

(表 1-1:内存问题 4 大伪装模式)

**关键事实**:**80% 的内存问题不是直接说"内存"——是"卡""闪退""被杀"**。工程师必须会"看穿伪装"。

### 1.2 5 大症状族总览(对应 26.2-26.6)

### 2.2 症状族依赖关系(因果链)

```
[RAM 满]
    ↓
[系统水位低:MemAvailable < 1GB]
    ↓
[压力传导链 5 大(26.5)]
    ↓

[症 1:CMA 满] → [症 5:拍照/视频失败]
[症 1:NUMA 失衡] → [症 4:性能下降]
[症 1:PSI full > 5%] → [症 5:整机卡死]
    ↓
[症 2:进程被杀 (lmkd / OOM killer)] ← 26.4
[症 3:Java OOM (堆溢出 / 大对象 / Bitmap / 线程)] ← 26.2
```

- 表(用户报):卡 / 闪退 / 被杀 / 系统慢
- 里(机制):15 章 ART/GC/Native/adj/PSI/lmkd
- 痕(产物):dumpsys / proc 节点 / logcat / mmstat2(26.7-26.9)
- 治(治理):26.6 五件套 + 5 大治理

## 4. 工程师 30 秒决策树

工程师线上 P0 收到内存相关问题,30 秒内决定先看哪篇:

```
收到 P0 内存问题
  │
  ├─ Q1: 是不是 "App 闪退"?
  │   YES → 看 logcat "OutOfMemoryError" 异常名
  │   ├─ "Java heap space" / "Failed to allocate" / "Out of memory on a N-byte allocation by Bitmap" / "pthread_create failed"
  │   │   → 跳 26.2 Java OOM
  │   └─ 都不是 → Q2
  │
  ├─ Q2: 是不是 "App 莫名被杀"?
  │   YES → 看 lmkd logcat + dumpsys dropbox
  │   ├─ "lmkd: Kill <pid> with adj <adj>" + adj 900+ = 真紧
  │   ├─ "lmkd: Kill <pid> with adj <adj>" + adj 100 = adj 误配
  │   └─ "Out of memory: Killed process" = 内核 OOM killer
  │   → 跳 26.4 进程被杀
  │
  ├─ Q3: 是不是 "App 卡但没闪退"?
  │   YES → 看 GC 日志 + gfxinfo
  │   ├─ "Background concurrent copying GC paused Nms" > 50ms
  │   ├─ "Janky frames > 5%"
  │   └─ 都不是 → Q4
  │   → 跳 26.5 压力传导
  │
  ├─ Q4: 是不是 "Native 堆涨但 Java 堆不涨"?
  │   YES → dumpsys meminfo:Native Heap 涨速 > 5MB/min
  │   → 跳 26.3 Native 增长
  │
  └─ Q5: 现场取证
      YES → 5 件套采集(proc/meminfo + dumpsys + mmstat2 + hprof + bugreport)
      → 跳 26.6 现场治理
```

(图 4-1:工程师 30 秒决策树)

**关键事实**:**30 秒内能定位到具体症状族,就能选对子文章**——这比"看 dumpsys 一行一行看"快 10 倍。

## 6. 总结:5 条 Takeaway

读这篇应能回答:

1. **"5 大症状族是什么?占比?"** ——
   - Java OOM 30% / Native 增长 20% / 进程被杀 20% / 压力传导 15% / 现场治理 15%
   - 对应 26.2 / 26.3 / 26.4 / 26.5 / 26.6
   - **80% 的内存问题不是直接说"内存"——是"卡""闪退""被杀"**

2. **"5 维速查矩阵怎么用?"** ——
   - 症状族 × 机制 × 产物 × 阈值 × 子文章——5 维交叉查
   - 看到 dumpsys 数字 → 矩阵定位 → 跳子文章深入

3. **"30 秒决策树怎么走?"** ——
   - Q1 闪退 → 26.2
   - Q2 被杀 → 26.4
   - Q3 卡 → 26.5
   - Q4 Native 涨 → 26.3
   - Q5 取证 → 26.6

4. **"三角分工是什么?"** ——
   - 15 章:WHY(机制)
   - 26.1-26.6:WHAT(症状识别)
   - 26.7-26.9:HOW READ(产物解读)
   - **三者缺一不可,但维度不同**

5. **"工程师实战路径?"** ——
   - 26.1 决策树 → 26.2-26.6 子章 → 26.7-26.9 调查工具书 → 15 章机制 → 26.6 治理
