## 二、逐项对比

### 2.1 工程基线（强锁项）

| 维度 | v4-Binder 同期 | v6 | 评价 |
|---|---|---|---|
| 应用层 / Framework 基线 | **AOSP 14.0.0_r1** | **AOSP 17.0.0_r1** (API 37, 代号 CinnamonBun) | v6 升级到 17 是为对齐 2026-08 当前主流旗舰 |
| Linux 内核基线 | android14-5.10 / 5.15 / android15-6.1 / 6.6 | **android17-6.18 / 6.19 / android14-6.1 / android15-6.6** | v6 引入 6.18 LTS(google 2025 旗舰) |
| AOSP 17 发布日 | 未声明 | **Beta 1 2026-02-13 + 正式版 2026-05~06 + QPR1 2026-09** | v6 强锁(v4 实战踩坑 2025-11-30 错时间线) |
| MGLRU 引入版本 | 未涉及 | **Linux 5.9 (commit ccd2a0d4, 2020-10)** | v6 强锁(v4 实战踩坑 5.10 误判) |

**哪个更好**：
- **v6 强锁 + 联网校准更好**。v4 只说"以 AOSP 14 为主线",没强锁具体发布日 / commit hash,实战中容易生成"2025-11-30 AOSP 14 发布"这种时间线幻觉。
- 但 v4 的"5.10 / 5.15 / 6.1 / 6.6"**多版本矩阵**也很有用——v6 反而简化为"6.18 LTS 为主",对长期演进的兼容不够。

**建议**：
- v6 补一个"5 版本内核矩阵"作为附录(android14-5.10 / android15-6.1 / android15-6.6 / android17-6.18 / android17-6.19)
- v6 的"强锁时间线"是必要约束

### 2.2 一站式写作模板

| 维度 | v4-Binder 同期 | v6 | 评价 |
|---|---|---|---|
| 5 段前言 | **内联**在文章正文(本篇定位 / 角色设定 / 上下文 / 写作标准) | **AUTHOR_ONLY:START/END 段包裹** + 顶部 blockquote 2-3 行 | 差异最大 |
| 自检报告 | 不强制 / 可选(在 # 写作标准 段提一句) | **独立 AUTHOR_ONLY 段** 26 项自检 | v6 强约束 |
| 章节结构 | 一句话开场 → 核心子问题 → 详细展开 → 风险地图 → 实战案例 → 总结 → 附录 A/B/C/D | **同 v4** 七节 + 附录 A/B/C/D + 前置素材/下一步 | 结构相同 |
| marker 规范 | **无强制** | **v6 §9.2 强制**(只能 `:START/:END` / 禁止嵌套 / 禁止新标签) | v6 实战沉淀 |
| 顶部 blockquote | 无强制 | **2-3 行**(基线 / 本篇角色 / 强依赖) | v6 强约束 |

**哪个更好**：
- **v4 的"内联前言"对作者友好**——所有元信息都在文章里,作者/审计者一眼能看到
- **v6 的"marker 包裹"对公开站友好**——读者视图剥离后只看正文,不背 5 段前言
- **两者各有优势**:
  - v4 风格 = 写作流(写时/校时直接看)
  - v6 风格 = 发布流(读者只看到核心)

**实测差异**(以 9.1 为例):
- v4 9.1：读者首次看到顶部就是 5 段前言,内容实际是"作者元信息",会**淹没读者**(5250 中文字,其中约 700 字是 5 段前言)
- v6 9.1：读者首次看到顶部是 2-3 行 blockquote(基线/本篇角色/强依赖),5 段前言在 AUTHOR_ONLY 段被剥离,公开站看不见

**建议**：
- **v6 风格更适合"生产 + 公开站发布"**——读者视图干净
- 但 v6 风格**对作者维护成本高**——必须维护 marker + 段配对 + 公开站剥离脚本
- 如果只是写给自己 / 内部技术分享,**v4 风格更顺手**

## 三、风格对比

### 3.1 v4 风格的优势

1. **结构扁平清晰**——5 段前言内联,作者一眼能看到所有元信息
2. **第 8 章 (适用场景) 列举**了 ART/Input/MM/IO/Socket/Binder 等 10+ 系列——**复用性强**
3. **反例库 12 条都有完整错例全文**——可读性极强,作者写时直接对照改
4. **破例适用场景清晰**——图表密度 / 实战案例 都能破例,理由充分
5. **章节结构 §3 模板实战好用**——7 节固定结构 + 附录 A/B/C/D,已多系列验证

### 3.2 v6 风格的优势

1. **实战坑全沉淀**——§10 / §11 / §12 / §13 都是 v4 实战 15 篇后沉淀的
2. **公开站友好**——AUTHOR_ONLY 段剥离后,读者只看正文
3. **多 agent 协作支持**——§13 子线程规范是 v4 没有的
4. **反 AI 自嗨词表系统**——20 个词,实战 15 篇总结
5. **verify 工具集工程化**——15+ 个 verify_*.py 工具,主线程 hygiene
6. **已知幻觉清单**——20+ 条 blacklist,实战沉淀
7. **校准后 hygiene 4 件套**——跑 verify / commit / 删临时 / 更新 memory
8. **verifier 复审机制**——独立子代理复审 + 强制 marker + 6 项 verify

### 3.3 v4 vs v6 哪部分应该合并

| 优势 | v4 强项 | v6 强项 | 合并建议 |
|---|---|---|---|
| **第 8 章 适用场景列表** | 列出 10+ 系列 | 仅"v5 实战 15 篇总结" | v6 补完整列表 |
| **§3 模板反例全文** | 12 条都有完整错例 + 正确姿势 | 20+ 条但部分没完整错例 | v6 补全每条错例 |
| **§9 破例表格** | 简单列"按 §X 处理" | 6 字段强制表格 | v6 强约束更好 |
| **§10 工程基线** | 无 | 完整 | v6 必备 |
| **§11 不臆想实操** | 仅"案例可验证"提一句 | 5 件套 + 3 级标签 | v6 必备 |

| **校准机制** | 3 轮(结构/硬伤/锐度) | 3 轮 + hygiene 4 件套 | v6 加 hygiene 是对的 |

## 四、结论

### 4.1 哪个更好？

**v6 整体更好**——它在 v4 基础上补齐了:
- 工程治理(§10 verify 工具集 / mavis-trash / git commit 规范)
- "不臆想"实操(§11 5 件套 + 3 级标签)
- 已知幻觉清单(§12 20+ 条 blacklist)
- 子线程协作(§13)
- 公开站友好(AUTHOR_ONLY 段剥离)

**但 v4 的几个点 v6 应该补回去**:
1. **§8 适用场景列表**——v4 列出 10+ 系列,实战复用性强;v6 只说"v5 实战 15 篇",弱化
2. **反例库"完整错例"**——v4 12 条每条都有错例+正确姿势;v6 20+ 条但部分只有错例
3. **破例适用场景"明确列表"**——v4 给出"横切型 3 张 / 演进型 3 张+对比表"等具体场景;v6 模板化但场景没列全

### 4.2 什么时候用哪个？

| 场景 | 推荐 | 理由 |
|---|---|---|
| **新系列首次启动** | v6 | 工程治理 + 已知坑 + 子线程协作都是必须 |
| **老系列小修小补** | v4 风格 | 简单,作者维护成本低 |
| **多 agent 协作** | v6 | §13 必备 |
| **生产 + 公开站发布** | v6 | AUTHOR_ONLY 段剥离读者友好 |
| **内部技术分享 / 个人学习** | v4 风格 | 5 段前言内联,作者一眼看到 |
| **首次写新作者** | v6 | verify 工具集防止"新作者第一篇就翻车" |
| **追溯历史 / 写 v4 当时系列** | v4 风格 | 保持时序一致 |

### 4.3 v6 应该改什么？

1. **补 §8 适用场景列表**——v4 的 10+ 系列列表有价值,v6 应保留
2. **反例库补全"正确姿势"**——v4 12 条都有, v6 20+ 条部分缺
3. **破例适用场景明确化**——v4 给"横切型 3 张 / 演进型 3 张+对比表"等具体场景
4. **多版本内核矩阵**——v4 给了 4 个,v6 应保留
5. **降低 v6 §13 子线程规范强度**——如果不是多 agent 场景,§13 大量内容不必要;可以拆成"高级主题"附录

### 4.4 v4 还有什么价值？

1. **5 段前言内联**——作者维护时一目了然,即使 v6 也有"在 AUTHOR_ONLY 段看 5 段前言"的额外步骤
2. **反例库错例全文**——v4 12 条的错例+正确姿势写得很好,v6 应借鉴
3. **§8 适用场景列表**——v4 列举的 ART/Input/MM/IO/Socket/Binder 等 10+ 系列,实战复用性强
