## 章节详细

### 第 42 章　稳定性指标体系（SLI / SLO）

> 可衡量的稳定性——指标是治理的语言。与第 37 章的分工：本章管**稳定性指标**，第 37 章管**性能指标**。

- 42.1 SLI / SLO / SLA 的定义与选取
- 42.2 核心指标：崩溃率 / ANR 率 / 卡死率 / 重启率
- 42.3 用户感知指标：客诉 / 评分 / 留存关联
- 42.4 指标采集口径与一致性
- 42.5 指标失真治理：避免「数字好看、体验变差」
- 42.6 指标看板与分级告警联动

**本章小结**：指标是治理的语言——口径不统一，后面所有讨论都是各说各话。

### 第 43 章　APM 架构与自研实践

> 稳定性团队的核心基建——从选型到自研。

- 43.1 APM 整体架构：采集 / 传输 / 存储 / 分析 / 告警
- 43.2 端侧采集：崩溃 / ANR / 性能 / 自定义事件
- 43.3 采集开销控制：采样 / 降级 / 熔断
- 43.4 后端设计：聚合 / 归因 / 去重
- 43.5 第三方选型对比与自研边界
- 43.6 数据应用：从数据到决策的闭环

**本章小结**：APM 是团队的眼睛——但采集开销失控会让 APM 自己变成稳定性问题。

### 第 44 章　告警体系与降噪

> 告警是行动的起点——设计不当会导致「狼来了」。

- 44.1 告警分级与触发条件设计
- 44.2 告警路由与 Oncall 联动
- 44.3 降噪：聚合 / 抑制 / 静默 / 同源合并
- 44.4 告警疲劳的度量与治理
- 44.5 告警有效性评估：准确率 / 召回率
- 44.6 告警响应 SLA 与闭环

**本章小结**：告警少而准远胜多而泛——没人看的告警等于没有告警。

### 第 45 章　变更管理与灰度发布

> 变更是稳定性的最大单一风险源——灰度是风险控制的核心手段。

- 45.1 变更分级与风险评估
- 45.2 灰度策略：百分比 / 机型 / 区域 / 用户群
- 45.3 灰度期指标监控与自动阻断
- 45.4 快速回滚与止血预案
- 45.5 配置化开关与远端降级
- 45.6 灰度平台能力建设

**本章小结**：没有灰度就没有稳定性——所有大故障几乎都能追溯到一次未灰度的变更。

### 第 46 章　AI-Native 调试

> AI 在稳定性领域的应用与边界——新工具、新方法、新风险。

- 46.1 LLM 辅助日志与 trace 分析
- 46.2 智能归因与相似问题聚类
- 46.3 告警智能聚合与降噪
- 46.4 Agent 工程化：工具契约 / 上下文管理 / 可回溯性
- 46.5 端侧 AI 与系统智能化带来的新稳定性问题
- 46.6 AI 的能力边界与责任划分

**本章小结**：AI 能加速定位但不能承担判断责任——它给假设，人给结论。
