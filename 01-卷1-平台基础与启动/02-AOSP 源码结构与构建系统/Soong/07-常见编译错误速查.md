## 0. 一句话定位

**AOSP 17 上 90% 的编译错能在 5 秒内定位——只要知道"错误信息 → 哪一类错 → 根因 → 5 秒修法"对应表。**

本文给 5 大类共 30 个常见错的速查表。**oncall 5 分钟内 80% 问题**在这里能直接解决。

## 1. 10 大 Soong 错误（按频率排）

### 1.1 错误 1：unknown property（最常见，30%）

```
error: unknown property "src" 
       (did you mean "srcs"?)
  at packages/apps/MyApp/Android.bp:3:5
```

**根因**：属性名拼错（src → srcs）

**5 秒修法**：

```python
# 错误
cc_library {
    name: "libfoo",
    src: ["src/*.cpp"],   # 拼错
}

# 正确
cc_library {
    name: "libfoo",
    srcs: ["src/*.cpp"],  # 正确
}
```

### 1.2 错误 2：module already defined（10%）

```
error: module "libfoo" already defined
  at packages/apps/MyApp/Android.bp:5:1
  at packages/apps/Other/Android.bp:3:1
```

**根因**：两个 Android.bp 定义了同名 module

**5 秒修法**：

```python
# 1. 找冲突的两个文件
$ grep -rn "name: \"libfoo\"" packages/

# 2. 改名其中一个
# libfoo → libfoo_v2
```

### 1.3 错误 3：missing required property（8%）

```
error: "name" is required
  at packages/apps/MyApp/Android.bp:1:1
```

**根因**：`name` 是必填，没写

**5 秒修法**：

```python
# 加 name
android_app {
    name: "MyApp",   # 必填
    srcs: [...],
}
```

### 1.4 错误 4：circular dependency（8%）

```
error: cycle detected in dependency graph
  libfoo depends on libbar
  libbar depends on libfoo
```

**根因**：A 依赖 B，B 依赖 A

**5 秒修法**：

```python
# 拆出公共 libcommon
# libfoo 依赖 libcommon
# libbar 依赖 libcommon
# libfoo 和 libbar 互不依赖
```

### 1.5 错误 5：visibility error（8%）

```
error: //vendor/foo:libbar is not visible to 
       //platform:libqux
```

**根因**：vendor 侧 module 默认 platform 不可见

**5 秒修法**：

```python
# libbar 加 visibility
cc_library {
    name: "libbar",
    visibility: ["//platform:__subpackages__"],
}
```

### 1.6 错误 6：property type error（6%）

```
error: property "srcs" expects []string, got string
  at packages/apps/MyApp/Android.bp:3:11
```

**根因**：属性类型错（应 []string 写了 string）

**5 秒修法**：

```python
# 错误
srcs: "src/*.cpp",  # string 类型

# 正确
srcs: ["src/*.cpp"],  # []string
```

### 1.7 错误 7：no rule to make target（6%）

```
error: no rule to make target 'libbar.so',
  needed by 'libfoo.so'
```

**根因**：依赖的 libbar 没编出来（删了 .bp / 编失败）

**5 秒修法**：

```bash
# 看 libbar 在不在
$ find out/target/product -name "libbar.so" 2>/dev/null
# 不在 → 编 libbar
$ m libbar

# 或检查 libbar Android.bp 是否存在
$ find packages -name "Android.bp" | xargs grep -l "name: \"libbar\""
```

### 1.8 错误 8：defaults not found（5%）

```
error: 'mydefaults' is not a default
```

**根因**：用了不存在的 defaults

**5 秒修法**：

```python
# 1. 找 mydefaults 定义
$ find packages -name "Android.bp" | xargs grep -A2 "cc_defaults" | grep "name: \"mydefaults\""

# 2. 加到 defaults 列表
cc_library {
    name: "libfoo",
    defaults: ["mydefaults"],   # 必须先定义
    srcs: ["src/*.cpp"],
}
```

### 1.9 错误 9：glob no match（5%）

```
warning: no files matched glob pattern 
         "src/**/*.cpp"
```

**根因**：glob 路径相对当前 .bp，**不是相对 workspace 根**

**5 秒修法**：

```python
# 错误
srcs: ["path/from/root/src/*.cpp"]  # 相对 workspace

# 正确
srcs: ["src/*.cpp"]  # 相对 .bp 所在目录
```

### 1.10 错误 10：APEX membership error（4%）

```
error: libfoo is not in any APEX, 
       but it should be in myapex
```

**根因**：标 `.apex_available` 的 module 没被任何 apex 收集

**5 秒修法**：

```python
# 1. 加到 apex 的 apex_defaults
apex_defaults {
    name: "myapex-defaults",
    // ...
    // 自动收集所有 .apex_available: "myapex" 的 module
}

# 2. 或显式 list
apex {
    name: "myapex",
    // ...
    binaries: ["mybin"],
    // ...
}
```

## 2. 5 大 Ninja 错误

### 2.1 错误 1：ninja file corrupt（最常见，35%）

```
ninja: error: out/soong/build.ninja: 
       ninja_required_version mismatch
```

**根因**：build.ninja 损坏（磁盘满 / 中断 / 权限）

**5 秒修法**：

```bash
# 重生成 build.ninja
$ rm out/soong/build.ninja
$ m
# 触发 Soong 重生成
```

### 2.2 错误 2：stale .o（25%）

```
FAILED: out/.../libfoo.o
clang: error: no such file or directory: 'src/foo.cpp'
```

**根因**：删了 .cpp 但 .o 还在

**5 秒修法**：

```bash
# 删陈旧 .o
$ rm out/.../libfoo.o
$ m libfoo
```

### 2.3 错误 3：depfile missing（15%）

```
warning: depfile 'libfoo.o.d' missing
```

**根因**：.d 文件丢失

**5 秒修法**：

```bash
# 删 .o 重编
$ rm out/.../libfoo.o
$ m libfoo
```

### 2.4 错误 4：dependency hash mismatch（15%）

```
ninja error: depfile 'libfoo.o.d' has been modified
```

**根因**：.d 改了但没触发重编

**5 秒修法**：

```bash
$ rm out/.../libfoo.o
$ m libfoo
```

### 2.5 错误 5：sandbox error（10%）

```
ninja: error: sandbox failed to start
```

**根因**：sandbox 工具缺失

**5 秒修法**：

```bash
# 1. 装 sandbox（Ubuntu）
$ sudo apt install bubblewrap

# 2. 关闭 sandbox
$ m SANDBOX_HOST_BLACKLISTED=true libfoo
```

## 3. 5 大 Link 错误

### 3.1 错误 1：undefined reference（最常见，40%）

```
libfoo.so: undefined reference to 'bar_func'
```

**根因**：声明了用 bar_func 但没 link libbar

**5 秒修法**：

```python
# 加 shared_libs
cc_library {
    name: "libfoo",
    srcs: ["src/*.cpp"],
    shared_libs: [
        "libbar",   # 加这个
    ],
}
```

### 3.2 错误 2：multiple definition（25%）

```
multiple definition of 'my_var'
```

**根因**：全局变量在多个 .cpp 定义

**5 秒修法**：

```cpp
// header
extern int my_var;  // 声明

// 一个 .cpp 定义
int my_var = 42;    // 定义

// 其他 .cpp 只能 extern
```

### 3.3 错误 3：linker version script error（15%）

```
ld: error: version script assignment of 'VERS_1.5' to symbol 'xxx' failed
```

**根因**：version script 写错

**5 秒修法**：

```python
# 检查 version_script
cc_library {
    name: "libfoo",
    version_script: "libfoo.map.txt",
    # 确保 libfoo.map.txt 里有 VERS_1.5 { global: xxx; };
}
```

### 3.4 错误 4：lld cannot find -l<lib>（10%）

```
ld.lld: error: unable to find library -lbar
```

**根因**：库路径不对

**5 秒修法**：

```python
# 1. 检查库在不在
$ find out/target/product -name "libbar.so"

# 2. 找不到时：
#    a) 库没编出来 → m libbar
#    b) 路径不对 → 加到 link path
```

### 3.5 错误 5：strip error（10%）

```
strip: error: invalid ELF file
```

**根因**：编错产物传给 strip

**5 秒修法**：

```bash
# 删重编
$ rm out/.../libfoo.so
$ m libfoo
```

## 4. 5 大 Clang 错误

### 4.1 错误 1：fatal error: 'foo.h' not found（35%）

```
fatal error: 'foo.h' file not found
```

**根因**：include 路径错

**5 秒修法**：

```python
# 1. 找 foo.h 在哪
$ find packages -name "foo.h"

# 2. 加 include_dirs
cc_library {
    name: "libfoo",
    include_dirs: ["path/to/foo.h"],
    # 或 export_include_dirs（让下游能用）
    export_include_dirs: ["include"],
}
```

### 4.2 错误 2：unused variable（25%）

```
warning: unused variable 'foo' [-Wunused-variable]
```

**根因**：定义了变量没用

**5 秒修法**：

```python
# 1. 删变量
# 2. 或 (void)foo;
# 3. 或改 .bp 关 -Werror
cflags: ["-Wno-unused-variable"],
```

### 4.3 错误 3：unused parameter（20%）

```
warning: unused parameter 'arg' [-Wunused-parameter]
```

**5 秒修法**：

```cpp
// 改 .cpp
void func(int /*arg*/) {  // 注释参数名
    // 或 (void)arg;
}
```

### 4.4 错误 4：redefinition（10%）

```
error: redefinition of 'foo'
```

**根因**：同一个 .cpp 多次 include 同一 header

**5 秒修法**：

```cpp
// 加 header guard
#ifndef MY_HEADER_H
#define MY_HEADER_H
// 内容
#endif
```

### 4.5 错误 5：incompatible pointer type（10%）

```
warning: incompatible pointer types 
         passing 'foo' to parameter of type 'bar'
```

**5 秒修法**：

```cpp
// 加 cast
func((bar)foo);
```

## 5. 5 大 SELinux 编译错误

**完整 SELinux 排错见 [06-Foundation/SELinux/06](../../05-安全基础（SELinux%20·%20AVB）/SELinux/06-常见稳定性问题：service-crash.neverallow.build-失败.md)，这里 5 个最常见**。

### 5.1 错误 1：neverallow violation（最常见，50%）

```
neverallow check failed
  for scontext=u:r:vendor_foo:s0
  tclass=capability
  permission: sys_admin
```

**5 秒修法**：见 [SELinux 06 §3](../../05-安全基础（SELinux%20·%20AVB）/SELinux/06-常见稳定性问题：service-crash.neverallow.build-失败.md)

### 5.2 错误 2：type duplicate（20%）

```
libsepol: conflicting definitions:
  type vendor_foo defined in
    /.../platform/vendor_foo.te:10
    /.../device/vendor_foo.te:8
```

**5 秒修法**：

```bash
# 删 device 侧的定义
# platform 侧已定义，device 不应重复
```

### 5.3 错误 3：file_contexts invalid regex（15%）

```
checkfc: invalid regex at /.../file_contexts:42
        pattern: /system/[**/]foo
```

**5 秒修法**：

```bash
# 修正则
# 错误：[**/]foo
# 正确：foo(/.*)? 或 foo/*
```

### 5.4 错误 4：sepolicy OOM（10%）

```
out/host/linux-x86/bin/checkpolicy: out of memory
```

**5 秒修法**：

```bash
# 1. 删未用的 .te
# 2. 升级编译机器
# 3. 用 CIL（编译更省内存）
```

### 5.5 错误 5：label 缺失（5%）

```
avc: denied { ... } tcontext=u:object_r:unlabeled:s0
```

**5 秒修法**：见 [SELinux 04 §6.5](../../05-安全基础（SELinux%20·%20AVB）/SELinux/04-AVC与avc_denied：从一次denied反推策略.md)

## 7. oncall 5 分钟决策树

```
[问题] 编译失败
  ↓
[1] 找错误信息第 1 行（5 秒）
  ├─ "error: " → Soong / Clang / Link 错
  ├─ "FAILED: " → Ninja 错
  ├─ "avc: denied" → SELinux 错
  └─ "warning: " → 警告（不阻塞，看情况）
  ↓
[2] 看错误信息前缀（5 秒）
  ├─ 错误信息含 Android.bp:  → Soong 错（[§1]）
  ├─ 含 .cpp: 或 .h:        → Clang 错（[§4]）
  ├─ 含 undefined / multiple → Link 错（[§3]）
  ├─ 含 neverallow / tcontext → SELinux 错（[§5]）
  └─ 含 ninja / .o            → Ninja 错（[§2]）
  ↓
[3] 查速查表（[§6] 30 错对照表）找对应错（30 秒）
  ↓
[4] 按 5 秒修法改（5-10 分钟）
  ↓
[5] 重新 m 验证（30 秒）
```

**总耗时**：5 + 30 + 10 = **15 分钟**（含重编译）
